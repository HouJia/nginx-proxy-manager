## 3. nginx 设计要点

### 3.1 匹配顺序

`location =` / `^~` 前缀优先于兜底 `location /`（QNAP）。  
因此 `/subapi/sub?` 不会误进 QNAP。

### 3.2 QNAP 与欢迎页

QNAP `/cgi-bin/` 会 `window.location = "/"`。  
**禁止**在 `location = /` 挂欢迎页；欢迎页仅 `/index/`。

### 3.3 subconverter（`/subapi`）

```nginx
location = /subapi {
    proxy_pass http://192.168.0.6:25500/version;
}
location ^~ /subapi/ {
    rewrite ^/subapi/(.*)$ /$1 break;
    proxy_pass http://192.168.0.6:25500;
}
```

### 3.4 sub-web（`/subw/`）与过渡补丁

**目标态**（sub-web 以 `VITE_BASE_PATH=/subw/` 构建后）：仅需 `location ^~ /subw/` 剥前缀反代。

**过渡态**（旧镜像 `base: "/"`）：脚本内保留：

- `sub_filter` 将 JS 中 `base:"/"` → `base:"/subw/"`
- 全局 `^~ /assets/`、`^~ /favicons/` 指向 sub-web（旧构建写死根路径）
- `sub_filter` 替换 `DEFAULT_BACKEND`、placeholder、`backendOptions`（见 `nas-qnap-npm-phase1-final.mjs`）

sub-web 新镜像上线后，可删除全局 `/assets/`、`/favicons/` 及大部分 JS `sub_filter`。

### 3.5 Jellyfin

`forward_path: /` + `location /jellyfin/` → 上游剥前缀；`X-Forwarded-Prefix /jellyfin`。

### 3.6 WebDAV

`proxy_headers_hash` 加大；`Authorization` 透传；`/home/` 单独 `location` 对应客户端路径。

### 3.7 证书

bind-mount QNAP LE：`/etc/stunnel` → 容器 `/etc/qnap-le`，脚本写入 `/data/custom_ssl/npm-1/`。

## 4. 部署步骤

```bash
# 本机
scp scripts/nas-qnap-npm-phase1-final.mjs nas-qnap:/share/Public/npm-phase1-final.mjs

# NAS
DOCKER=/share/CACHEDEV1_DATA/.qpkg/container-station/bin/docker
"$DOCKER" cp /share/Public/npm-phase1-final.mjs nginx-proxy-manager:/tmp/npm-phase1-final.mjs
"$DOCKER" exec nginx-proxy-manager node /tmp/npm-phase1-final.mjs
```

续订证书后：`scripts/nas-qnap-reload-npm-le.sh`（放 NAS `/share/Public/` 并按脚本内说明执行）。

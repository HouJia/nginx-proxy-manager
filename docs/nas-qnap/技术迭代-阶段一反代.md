# 技术迭代：QNAP NAS 阶段一 — NPM 反代与路径规划

> **本仓库职责**：Nginx Proxy Manager 配置脚本、欢迎页静态文件、LE 证书同步、nginx `location` 编排。  
> **关联仓库**：`sub-web`（前端子路径）、`SubConverter-Extended`（API 容器）。  
> **外网入口**：`https://<你的域名>:<HTTPS端口>`（示例 `https://nas.example.com:8443`）  
> **版本**：2026-05-16

## 1. 本迭代在 NPM 侧交付什么

| 交付物 | 路径 |
|--------|------|
| 一键写入 NPM DB + 生成 nginx | `scripts/nas-qnap-npm-phase1-final.mjs` |
| LE 续订后重载 NPM | `scripts/nas-qnap-reload-npm-le.sh` |
| 导航静态页 | 脚本生成 `/data/nginx/custom/welcome/index.html` |

不在本仓库改：sub-web 前端、subconverter 二进制、QNAP 系统服务。

## 2. 路径总表（示例域名）

| 外网路径 | 上游 | 说明 |
|----------|------|------|
| `/index/` | NPM 静态 `welcome` | 家庭服务导航，**不占 `/`** |
| `/` | `https://<NAS-IP>:5001` | QNAP（URI 原样） |
| `/subapi` | 301 → `/subapi/version` | 规范 URL |
| `/subapi/*` | `http://<NAS-IP>:25500/*` | 剥 `/subapi` 前缀，含 `/sub?` |
| `/subc` | 301 → `/subapi/version` | 旧书签兼容 |
| `/subw/` | `http://<NAS-IP>:58081/` | 剥 `/subw` → sub-web |
| `/jellyfin/` | `http://<NAS-IP>:8096/` | 剥 `/jellyfin` |
| `/webdav/` | `https://<NAS-IP>:5008/` | WebDAV |
| `/home/` | `https://<NAS-IP>:5008/home/` | WebDAV 客户端 PROPFIND |

## 3. nginx 设计要点

### 3.1 匹配顺序

`location =` / `^~` 前缀优先于兜底 `location /`（QNAP）。  
因此 `/subapi/sub?` 不会误进 QNAP。

### 3.2 QNAP 与欢迎页

QNAP `/cgi-bin/` 会 `window.location = "/"`。  
**禁止**在 `location = /` 挂欢迎页；欢迎页仅 `/index/`。

### 3.3 subconverter（`/subapi`）

```nginx
location = /subapi { return 301 $scheme://$http_host/subapi/version; }
location ^~ /subapi/ {
    proxy_set_header X-Forwarded-Prefix /subapi;
    rewrite ^/subapi/(.*)$ /$1 break;
    proxy_pass http://<NAS-IP>:25500;
}
```

### 3.4 sub-web（`/subw/`）与过渡补丁

**目标态**（sub-web 以 `VITE_BASE_PATH=/subw/` 构建后）：仅需 `location ^~ /subw/` 剥前缀反代。

**过渡态**（旧镜像 `base: "/"`）：脚本内保留：

- `sub_filter` 将 JS 中 `base:"/"` → `base:"/subw/"`
- 全局 `^~ /assets/`、`^~ /favicons/` 指向 sub-web（旧构建写死根路径）
- `sub_filter` 替换 `DEFAULT_BACKEND`、placeholder、`backendOptions`（见 `nas-qnap-npm-phase1-final.mjs`）

sub-web 新镜像上线后，可删除全局 `/assets/`、`/favicons/` 及大部分 JS `sub_filter`。

### 3.5 Jellyfin

`forward_path: /` + `location /jellyfin/` → 上游剥前缀；`X-Forwarded-Prefix /jellyfin`。

### 3.6 WebDAV

`proxy_headers_hash` 加大；`Authorization` 透传；`/home/` 单独 `location` 对应客户端路径。

### 3.7 证书

bind-mount QNAP LE：`/etc/stunnel` → 容器 `/etc/qnap-le`，脚本写入 `/data/custom_ssl/npm-1/`。

## 4. 部署步骤

### 4.1 新电脑从零部署（clone → NAS 生效）

前置：NAS 上 **Nginx Proxy Manager** 容器已运行；本机可 `ssh nas-qnap`（或你的 SSH 别名）；已知 **NAS 内网 IP** 与各服务端口。

```bash
# 1) 本机 clone（HouJia 主线 hjsmaster，与 Extended / sub-web 一致）
git clone git@github.com:HouJia/nginx-proxy-manager.git
cd nginx-proxy-manager
git checkout hjsmaster

# 2) 拷脚本到 NAS（路径可自定）
scp scripts/nas-qnap-npm-phase1-final.mjs nas-qnap:/share/Public/npm-phase1-final.mjs

# 3) SSH 到 NAS，注入内网 IP / 公网域名后执行（必填，勿用脚本内占位默认值）
DOCKER=/share/CACHEDEV1_DATA/.qpkg/container-station/bin/docker
"$DOCKER" cp /share/Public/npm-phase1-final.mjs nginx-proxy-manager:/tmp/npm-phase1-final.mjs
"$DOCKER" exec \
  -e NAS_LAN_IP=192.168.x.x \
  -e NAS_PUBLIC_HOST=你的域名.example \
  nginx-proxy-manager node /tmp/npm-phase1-final.mjs
```

脚本会写入 NPM 数据库、生成 nginx 配置并 `nginx -s reload`。**不是**在本机 `docker exec` 部署 subconverter/sub-web；后两者见 **SubConverter-Extended** / **sub-web** 各自 `deploy/nas/deploy-to-qnap.sh`。

| 环境变量 | 含义 | 示例 |
|----------|------|------|
| `NAS_LAN_IP` | QNAP 与各 Docker 服务所在内网 IP | `192.168.0.6` |
| `NAS_PUBLIC_HOST` | 欢迎页 `<title>` 与文档用公网域名（无 `https://`） | `houjia.mycloudnas.com` |

### 4.2 命令速查

```bash
# 本机
scp scripts/nas-qnap-npm-phase1-final.mjs nas-qnap:/share/Public/npm-phase1-final.mjs

# NAS
DOCKER=/share/CACHEDEV1_DATA/.qpkg/container-station/bin/docker
"$DOCKER" cp /share/Public/npm-phase1-final.mjs nginx-proxy-manager:/tmp/npm-phase1-final.mjs
"$DOCKER" exec -e NAS_LAN_IP=<NAS-IP> -e NAS_PUBLIC_HOST=<你的域名> nginx-proxy-manager node /tmp/npm-phase1-final.mjs
```

续订证书后：`scripts/nas-qnap-reload-npm-le.sh`（放 NAS `/share/Public/` 并按脚本内说明执行）。
